# Roc October 14 compiler and basic-cli upgrade

The upgrade selects the published `nightly-2026-10-14-38a3029` and the immutable
basic-cli `0.26.0-rc2` package. The platform requires October 12 or later.
All ten public gallery applications type-check and reproduce their committed
PDFs byte for byte. Package scope, public capability gates, work counters and
PDF snapshots stay unchanged.

## Measurement and comparison controls

All 332 proposed-compiler cases completed on arm64mac and x64musl. Both targets
have identical measured allocation counts and requested-byte totals, measured
independently rather than copied between targets. Builds use `--opt=dev` and
`--no-cache`; Zig is 0.16.0 with the ReleaseFast test host. Linux binaries are
cross-compiled on the same Mac and executed in the local linux/amd64 container.
No timing, throughput or peak-memory acceptance target applies.

The incoming workspace had an October 4 pin with older recorded baselines.
October 4 cannot compile tests/transparency/main.roc: the Mac build returns
OutOfMemory or is killed, the Linux build segfaults, and a single internal
compiler worker and pre-fix source do not resolve it. October 3 also segfaults.
The complete working control is the published October 1 compiler, a descendant
of the previous checked-in local September 30 compiler. October 4 measurements
for its other 320 cases are retained as an additional control, explicitly
excluding the twelve unavailable transparency cases.

## Baseline decision

The October 1 working control reproduces every recorded allocation count,
requested-byte value and work vector on both targets: zero baseline differences
across all 332 cases. The October 14 measurements change 329 cases on each
target; 328 allocation counts decrease, one increases by 15 and three cases are
unchanged. Every changed case requests fewer bytes, with no ceiling violation.

## Source changes and allocation causes

Body-frame validation now uses checked signed subtraction and returns a located
layout diagnostic on overflow. Negative-number formatting computes its unsigned
magnitude so I64.lowest also formats without overflow. Extreme horizontal and
vertical margin regression tests and the retained eight-byte fuzz failure
exercise typed rejection. The scalar checks allocate nothing on the ordinary
path: old and new reference fixtures have identical pre-fix/post-fix allocation
histograms under each compiler.

The retention platform now declares its own targets directory. The test-only
Zig build installs its host there and copies the existing pinned Linux startup
and libc inputs into that generated directory. This satisfies the new compiler
rule that targets stay inside the platform directory.

The [21-pair allocation-size trace record](roc-nightly-2026-10-14-allocation-traces.csv) covers builder and source-cache scale
pairs, font inspection, resource graphs, rich inline text, masks, serialization,
reference-document scale pairs and the observed outliers. Builder, source-cache,
font, graph, rich-paragraph, mask and serializer histograms match between October
4 and 14. Reference invoice x50 and x500 each lose the same 26 allocations and
2240 requested bytes. Reference rejection variants lose 7790 allocations and
994224 bytes. These are compiler changes with unchanged work.

Minimal tagged output gains twelve allocations and 298 bytes, consisting only
of 9/10/32-byte allocation events and 56-byte reallocations. Ordered multi-face
output gains four events and 106 bytes in the same small-buffer sizes. Code
holds x14 loses eight events but gains 5856 requested bytes: two 3344-byte growth
steps account for the difference. Its x140 pair loses ten events and 832 bytes;
the small-case growth-schedule change does not repeat at the larger scale.

Against the complete October 1 control, reference rejection variants rise from
162201 to 162216 events (+0.0093%), while requested bytes fall from 116083140 to
114180841 (-1902299). The size histogram adds 12819 events and removes 12804:
small 16-byte allocations and 24/40/72-byte growth events replace other
materializations and larger buffer-growth requests. The old 72-byte fresh
allocation bucket alone loses 7739 events. This is a net materialization and
capacity-schedule change across the same fixed set of 24 rejection scenarios;
its work vector and carrier PDF remain identical. The new source has exactly
the same reference-case size histograms before and after the arithmetic fix,
so the feature correction does not hide a separate allocation increase.

## Validation scope and cache constraints

The proposed compiler passes the full Roc validation plan, all 332 snapshot and
work checks on each target, all ten gallery byte comparisons, all nine bounded
fuzz campaigns at 2000 executions each and replay of the original theme crash.
The initial fuzz comparison used the workspace's local roc-fuzz checkout.
For CI portability, all nine targets now pin the immutable roc-fuzz 0.4.3 release,
which publishes the same redundant-type-exposure compatibility fix. The bounded
campaign is also rerun against that published package before merge.

October 4's cached authoring expect fails while its uncached expect and standalone
builder/simple executions pass. Evidence fixtures therefore retain the existing
no-cache policy. A concurrent shared-cache LLVM fuzz build lost its temporary
static-data object directory; a dedicated ROC_CACHE_DIR completed the build and
campaign. The full final fuzz lane also passes in that dedicated cache.

No PDF snapshot, algorithmic work vector or scenario input is accepted as changed.
Exact-baseline verification reuses the retained no-cache executables from
the measurements, protects build inputs with SHA256 checks and executes all cases
again against the accepted metrics through scripts/test.py.
