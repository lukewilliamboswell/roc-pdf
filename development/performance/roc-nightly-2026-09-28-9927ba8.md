# Roc nightly 2026-09-28 allocation review

## Scope and cause

This upgrade moves the pinned compiler from `nightly-2026-09-26-d6267b4` to
`nightly-2026-09-28-9927ba8` (176 upstream commits). The motivation is Roc
#11777: the September 26 compiler intermittently crashed (SIGSEGV or abort) in
`roc check tests/authoring/authoring.roc`, in six of eight standalone attempts
and in every recent full harness run. Upstream commit 329a48a04d ("Don't
classify restored hoisted consts as graph-free dispatch", merged in #11779) fixes
it and is contained in the new nightly.

The only source change is formatting. The new `roc fmt` removes a blank line
between a block's opening brace and a leading `##` comment (upstream
5a7fa84437), which 29 files had. Only whitespace changes. No syntax, builtin,
public API, or roadmap capability boundary changes.

## Crash resolution

The check was `roc check package/main.roc` followed by `roc check
tests/authoring/authoring.roc`, each iteration from a fresh empty
`XDG_CACHE_HOME`:

| Compiler | Iterations | Crashes |
| --- | ---: | ---: |
| `nightly-2026-09-26-d6267b4` | 4 | 1 (abort, exit 134, in the authoring check) |
| `nightly-2026-09-28-9927ba8` | 10 | 0 |

A full cold-cache `--allocation-baselines` run with the new compiler passed
all 264 cases without a compiler crash.

## Measurement

Allocation measurements use Linux x86_64 (`x64musl`), Roc `--opt=dev`, the
existing `before_fixture_main` boundary, and fixtures built with `--no-cache`.
The old-toolchain reference is the current `tests/spec.json`, which passes on
the September 26 compiler on the same host. The comparison command is
`ROC=<new> XDG_CACHE_HOME=<empty> ./scripts/test.py --compare-baselines
--baseline-report <report> --jobs 6`. Snapshots and deterministic work stay
strict in comparison mode. No elapsed-time performance claim is made.

- All 264 PDF snapshots are byte-identical. All work vectors are unchanged.
- 109 cases change allocations or allocated bytes, and 155 are identical.
  Every change is in the
  [allocation comparison](roc-nightly-2026-09-28-allocations.csv).
- Allocations: 84 cases decrease, 20 increase, and 160 are unchanged. The
  per-case delta ranges from -6,004 to +2 (median over changed cases: -4). As
  a percentage, it ranges from -2.22% to +0.14%. The suite total falls from
  5,579,774 to 5,562,979 (-0.30%).
- Allocated bytes: 69 cases decrease, 40 increase, and 155 are unchanged. The
  per-case delta ranges from -192,032 to +320 bytes (-0.38% to +0.46%). The
  suite total falls by 526,744 bytes (-0.02%).
- No case approaches the 10% allocated-bytes ceiling.

## Outliers investigated

**Linear decreases in layout, tables, semantics, and templates.** The largest
decreases scale with the input:

| Scenario | x-small | x-large | Removed per unit |
| --- | ---: | ---: | ---: |
| Keep groups and lists (x50 / x500) | -604 | -6,004 | 12 |
| Adversarial heading chain (x50 / x500) | -204 | -2,004 | 4 |
| Page templates letter (x6 / x20 / x200) | -284 / -340 | -1,060 | about 4 per page |

In every family, the removed bytes are 30 to 32 per removed allocation. For
example, 6,004 allocations and 192,032 bytes are removed. So one small
fixed-size allocation per item is gone; no large buffer shrinks. The range
includes several ARC and uniqueness changes: 24e985841f and f5ac8897f7 build
compile-time lists fresh, 01e5a3e0df composes uniqueness seed masks through
direct calls, e8050b0c1c marks borrowed structs as shells, and 616089c4e7
carries candidate origins through record fields. These changes remove
per-item copies of small values. The deltas are decreases; they do not change
any traversal or work counter.

The table cases keep a fixed decrease at both scales (invoice x50 and x500:
-840 each). The structural kernel is identical. Balanced 4,096-page emission
stays at 29,679.

**Fixed increases in forms, masks, and transparency.** Most form,
soft-mask, and opacity cases gain exactly one allocation of 136 bytes. The
form, soft-mask, and transparency atomic negatives gain two (272 bytes). The
color-image cases gain one allocation and 160 to 208 bytes, or 48 bytes with
no count change. The increase is the same at both scales (shared mask reuse
x100 and x1000: +1 allocation, +136 bytes; distinct opacity states x100 and
x1000: +1, +136). So it is a per-program constant, not per-form work. It
matches the upstream compile-time evaluation changes: d4ceb600b1, f0d98bd158,
and 44e2d04fbc evaluate literal roots inside the program being built,
5285bf179e merges identical frozen nodes, and f4a81572cd declares all-zero
static data as zero-fill. Those changes move one small constant between
compile-time materialization and runtime.

**Text layout: one or two fewer allocations, a few more bytes.** Cases that
use the bundled fixed font lose one or two allocations and gain 8 bytes per
removed allocation. The CJK and supplementary-plane cases keep their count and
gain 48 bytes. The shift is the same at both scales (ordered multi-face facade
x1000 and x10000: -1 allocation, +8 bytes). It comes from the same
constant-materialization change, not from shaping or per-glyph work.

## Open blockers before merging the pin

1. **roc-fuzz release.** The September 26 and later compilers check the
   `packages { roc: ... }` pin inside downloaded platforms. roc-fuzz 0.4.1 pins
   `nightly-2026-09-26-d6267b4`, so `roc check` on every `fuzz/*.roc` target
   reports a version-mismatch warning, and the harness fails on it. The fuzz
   target URLs must move to a roc-fuzz release pinned to
   `nightly-2026-09-28-9927ba8`; upstream roc-fuzz PR #42 prepares that update.
   The measurements above used a local cache copy of roc-fuzz 0.4.1 with only
   its pin string edited. That copy is not part of this change.
2. **LLVM `roc build --fuzz` segfault.** The new compiler crashes with SIGSEGV
   in `roc build --fuzz fuzz/facade_structure.roc`. It crashes on every
   attempt, including with `--no-cache` and with the unmodified roc-fuzz
   package. `fuzz/facade_output_equivalence.roc` builds on a fresh cache but
   crashes on a warm one. `nightly-2026-09-27-a3ce7f1` and the September 26
   compiler build both targets, and the September 26 compiler passes the whole
   bounded fuzz lane. So the regression lies in
   `a3ce7f1..9927ba8` (the #11797 omnibus merge, #11779, #11795, and #11796).
   It needs an upstream issue. The dev-backend harness, examples, and bundle
   are unaffected.
