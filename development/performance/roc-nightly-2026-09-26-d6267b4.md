# Roc nightly 2026-09-26 allocation review

## Scope and measurement

This upgrade moves the pinned compiler from `nightly-2026-08-18-e9be50a` to
`nightly-2026-09-26-d6267b4`. Public examples use basic-cli 0.23.0; fuzz targets use roc-fuzz 0.4.1. The contract
fixture compares opaque identities through their public accessors; the registry
fuzzer now varies the rejected built-in policy identity with its input.
Neither change widens the public API or a roadmap capability boundary.

Allocation measurements use Linux x86_64 (`x64musl`), Roc `--opt=dev`, Zig
0.16.0 with a `ReleaseFast` host, and the existing `before_fixture_main`
boundary. The old compiler passed all 218 scenarios with the original baselines
on the same host. The comparison command is `ROC=<compiler> ./scripts/test.py
--compare-baselines --jobs 4`; snapshots and deterministic work remain strict in
comparison mode. No elapsed-time performance claim is made.

## Copying regressions fixed before accepting new counts

The new backend exposed two losses of list uniqueness across fallible loops.
GDB breakpoints on `roc_alloc` and `roc_realloc`, activated at `roc_main` or
`roc_host_reset_allocations`, recorded call stacks and requested byte sizes.
On x86_64 the size argument is `rdi` for allocation and `rsi` for reallocation.
These byte totals include reallocations and are allocation traffic, not peak
live memory. The traced fixtures were built with `--opt=dev --debug`.

The facade shaping preparation initialized two exact-length lists and filled
indexed slots through fallible `List.set` matches. Under the new compiler both
lists were copied per occurrence. At 1,000 paragraphs those two allocation
sites requested 40,417,024 bytes; at 10,000 they requested 4,004,161,024 bytes.
Preparation now reserves the validated exact capacity and appends sequentially.
Existing cardinality, occurrence, source, ownership and limit checks remain;
the resulting dense stores, label-before-body order and work are identical.

Ordered multi-face line preparation appended in both a label arm and a body
arm of its fallible loop. The growing request list was copied per block:
999 copies requested 16,023,960 bytes at 1,000 paragraphs. Preparation now
validates the optional label and body first, then consumes the list once in a
small helper which appends the label before its body. It preserves physical-run
coverage and logical indices. No extra traversal or retained intermediate list
is introduced.

| Scenario | Old compiler, final source | New compiler, before its fix | New compiler, fixed |
| --- | ---: | ---: | ---: |
| Batch shaping, 1,000 paragraphs | 253 | 3,284 | 1,276 |
| Batch shaping, 10,000 paragraphs | 285 | 21,316 | 1,308 |
| Ordered multi-face facade, 1,000 paragraphs | 241 | 1,305 | 319 |
| Ordered multi-face facade, 10,000 paragraphs | 268 | 10,327 | 346 |

The ordered pre-fix column already includes the shaping fix. Final source
retains the old compiler's original counts at both scales. New-compiler total
requested bytes after the fixes scale from 2,086,326 to 19,189,854 for shaping
and from 3,820,398 to 34,992,014 for ordered multi-face layout. Allocation counts
increase by only 32 and 27 respectively for tenfold input. These measurements
remove the quadratic copying instead of accepting it in a new baseline.

## Remaining compiler-dependent allocation changes

A focused font-inspection probe separated a top-level constant inspection of
the bundled 166,300-byte font from an inspection of identical bytes whose first
byte depends on the runtime argument count. Both return the same component,
table and coverage counts (1,713, 17 and 26).

| Probe | August 18 | September 26 |
| --- | ---: | ---: |
| Top-level constant inspection | 1 | 980 |
| Runtime-dependent inspection | 4,407 | 981 |

The old compiler precomputes the constant inspection. The new compiler performs
that inspection at runtime, adding 979 allocations; conversely its genuinely
runtime-dependent inspection uses substantially fewer allocations. The new
constant probe's trace includes 944 small component-list allocations totaling
67,968 bytes. This accounts for the dominant fixed-font increase without
implying changed font traversal or per-paragraph work. The full font fixture
moves from 40 to 1,063 allocations, and fixed-font batch shaping retains a fixed
1,023-allocation difference at both input sizes after the copying fix.

Other families combine this materialization change with backend list/ARC
lowering changes. Repeated fixed-font negative paths repeat the constant cost
(for example navigation facade negatives increase by 9,804), while dynamic
font inspection and dense resource graphs decrease substantially. Structural
4,096-page emission decreases from 134,277 to 125,530; dense resource graph
planning decreases from 28,122 to 12,245. DEFLATE decreases from 121 to 92;
traced requested bytes decrease from 684,087 to 681,066 with the same 524,296-byte
maximum request. These are allocation changes, not reduced deterministic work.

All 218 cases and their Linux deltas are recorded in the
[allocation comparison](roc-nightly-2026-09-26-allocations.csv); 215 change and
three remain identical. The paired target records in `tests/spec.json` retain
the existing target-parity contract. The macOS candidate values require an
exact comparison against all 218 measurements from the supported-host CI run
before merge; Linux measurements alone do not establish macOS parity. PDF snapshots,
work vectors, dimensions, structural validators and retention evidence must
remain exact; none is rebaselined for this upgrade. Supported-host CI is required
before merging the compiler pin.

## Reproducing the font materialization probe

Save this as `.roc-pdf-tmp/font-materialization.roc`, build it with each compiler
using `roc build --opt=dev --target=x64musl --output=<binary> <source>`, and run
`<binary> static` and `<binary> runtime`. Both commands have two process
arguments, so the runtime byte expression evaluates to the font's original
zero byte. The test platform reports allocations at the usual fixture boundary.

```roc
app [main!] { pf: platform "../tests/platform/main.roc", pdf: "../package/all.roc" }
import pdf.KernelFont
import "../vendor/fonts/RocPdfSans-Regular.ttf" as font_bytes : List(U8)
inspection = KernelFont.inspect(font_bytes, KernelFont.Limits.make({max_bytes: 200000, max_cmap_mappings: 10000, max_glyphs: 10000, max_tables: 32}))
main! : List(Str) => { bytes : List(U8), work : List(U64) }
main! = |args| {
    limits = KernelFont.Limits.make({max_bytes: 200000, max_cmap_mappings: 10000, max_glyphs: 10000, max_tables: 32})
    inspected = if args.get(1) == Ok("runtime") {
        bytes =
        match font_bytes.set(0, (args.len() - 2).to_u8_wrap()) {
            Ok(value) => value
            Err(_) => crash "probe input"
        }
        KernelFont.inspect(bytes, limits)
    } else { inspection }
    font = match inspected {
        Ok(value) => value
        Err(_) => crash "probe inspection"
    }
    { bytes: [], work: [font.components.len(), font.tables.len(), font.coverage.len()] }
}
```
