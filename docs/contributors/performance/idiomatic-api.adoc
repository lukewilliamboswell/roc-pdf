= Idiomatic API: records with defaults

`Theme`, `Pdf.Options`, `Theme.Scope`, and the configuration of the block
constructors are transparent nominal records (`:=`). Each presentation field
declares its built-in value as a `??` default. A caller writes only the
fields it changes, and `{}` uses all defaults.

The document title, language, contents, alternative text, captions, table columns and rows, and font validation limits stay required.

Each sub-record with defaults has its own nominal type. See `BodyStyle`, `TitleStyle`, `HeadingStyle`, `Headings`, `InlineRoles`,
`InlineStyle`, `LinkStyle`, `TableStyle`, `BodyFills`, and `PageMargin`. A
partial nested literal is completed from its own type's defaults, so a
partial `title` uses its declared title size.

The following tags express inheritance.

* A style's face is `ThemeFace` (the theme's `face`) or `Face(id)`.
* A heading level is `SameAsAll` or `Own(style)`.
* An inline role's color, face, and scale are `Inherited` until set.

The getters that preparation reads (`body_style`, `title_style`,
`heading_level_style`, and `inline_*`) resolve these tags into `TextStyle` before shaping.

Defaults supply documented construction values. Preparation validates each supplied field and reports a located diagnostic for an invalid value. Changing a `??` default is a reviewed
package-version change. The xref:architecture.adoc#high-level-api-is-the-primary-product[architecture] records these rules.
