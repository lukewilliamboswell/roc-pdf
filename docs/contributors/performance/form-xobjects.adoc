[#contributor-form-xobjects]
= Form XObject identity and placement ownership

Use the resource graph for physical Form XObject identity. Validate a form's
geometry, direct dependencies, and placement multiplicity before emitting its
definition or any invocation.

[#contributor-form-xobjects-the-semantic-and-tagging-model]
== The semantic and tagging model

*Decision: placement-site tagging over ownership-neutral physical forms.*

[arabic]
. A Form XObject's content stream never contains structure-bearing marked
content: no MCIDs, no `/StructParents`, no `/StructParent`, and no OBJR.
Form streams may contain non-structural presentation sequences (the
existing `ActualText` spans emitted by text lowering) because those carry
no ParentTree ownership.
. Every meaningful placement is tagged in the _consuming page content
stream_: the placing scene group is fragment-owned, so the existing
`/P <</MCID n>> BDC … EMC` wrapper (ISO 32000-2, 14.6.2: content painted by
a `Do` inside a marked-content sequence is part of that sequence) encloses
the balanced `q <matrix> cm /XOn Do Q` invocation. Artifact placements are
likewise enclosed by the group's `/Artifact … BDC … EMC` wrapper.
. MCIDs, page `/StructParents`, and ParentTree rows therefore remain exactly
the page-stream facts the tagged-visual tagged plan already produces. No form
stream acquires a ParentTree mapping, so ISO 32000-2's stream-scoped
content-item rules (14.7.5.4: an MCID in a non-page stream needs an MCR
with `/Stm` and the stream's own `/StructParents` key) never apply to
emitted output.

[#contributor-form-xobjects-text-inside-forms]
== Text inside forms

* A form that paints text (directly or through nested forms) must be
instantiated exactly once: every `Text.RunId` is drawn exactly once
globally, matching the existing run-ownership contract. Placing a
text-bearing form more than once (any placement multiplicity across the
DAG) is the stable rejection `TextFormMultiplyPlaced`; text reachable under
an artifact owner is `ArtifactTextInForm`, the form-DAG analogue of the
existing `ArtifactTextUnsupported`.
* The run's fragment ownership is the owner of the form's unique placement
chain, resolved iteratively over the DAG (no recursion). The fragment's
MCID wraps the placement in the page stream; `ActualText`, `ToUnicode`,
CID, and subset behavior are unchanged because the same
`KernelPdfText.ScenePlan` run lowering produces the in-form text operators.
* Two authored text-bearing forms whose canonical recipes are byte-identical
(same glyphs, font, paint, geometry — which requires their occurrences'
presentation to be identical) deduplicate to one physical stream; each
placement still extracts through its own MCID and occurrence.

[#contributor-form-xobjects-logical-order-versus-paint-order]
== Logical order versus paint order

Reading order continues to come only from the semantic content spine; MCIDs
are assigned from page paint order; the `/K` order of structure elements is
spine order. Form placement order participates in paint order exactly like any
other painted group, so the `order` scenario proves a document whose spine
order is intentionally different from its form paint order.

[#contributor-form-xobjects-form-identity]
== Form identity

Canonical recipes include validated commands, geometry, numeric operands,
text and paint, and exact canonical identities for nested resources. The
digest identifies an equality candidate. Exact recipe checks prove reuse.
Identity carries no MCID, object number, or logical position. Direct
dependencies provide each stream's resource dictionary.

[#contributor-form-xobjects-complexity-ownership-and-retention-contracts]
== Complexity, ownership, and retention contracts

Use the existing acyclic dependency graph and dense placement facts.
Traversals count direct edges and commands. A reused artifact or
visual-only form gets one generated compressed stream. Each consuming
page site retains its own occurrence or artifact association. The
emitter consumes the generated payload through its final declared use.

[#contributor-form-xobjects-evidence]
== Evidence

`fuzz/GraphicsTransformModel.roc` compares transform and graphics-stack
behavior with ISO 32000-2 §8.3.4. The Form XObject cases in
`tests/spec.json` pin scaled artifact reuse, distinct recipes, nested
forms, logical versus paint order, and bounded rejection of conflicting
ownership. `scripts/check_forms.py` verifies the emitted structural
wrappers, per-stream dictionaries, and paint. The opt-in matrix
`scripts/check_form_renderers.py` compares the original files in pinned
independent readers.

See https://github.com/lukewilliamboswell/roc-pdf/blob/a6d1bde3028d51955b96af3ba1a183855a92cd2d/docs/contributors/performance/form-xobjects.md[the archived design and measurements].
