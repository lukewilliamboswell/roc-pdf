[#contributor-metadata-output-intent]
= Canonical metadata, document language, and sRGB output intent

Metadata validation produces typed facts before layout. The catalog and
XMP share the validated language. XMP also consumes the validated title,
timestamps, and selected profile. Conformance validation consumes these facts and verifies the
emitted outputs through the case-specific validators.

[#contributor-metadata-output-intent-typed-facts-and-validation-policies]
== Typed facts and validation policies

All metadata facts originate in typed authoring data and cross the compiler
stages explicitly; no later stage re-parses, re-derives, or recovers a value
from serialized bytes.

*Language.* The language-tag reference is BCP 47 / RFC 5646. The accepted subset is the canonical-case form
`language["-" script]["-" region]`: a two- or three-letter lowercase primary
language, an optional four-letter titlecase script, and an optional
two-letter uppercase or three-digit region. Three rejection families keep
the boundary honest and the diagnostics stable:

* `MalformedLanguageTag` — shapes RFC 5646 itself cannot produce (`en_AU`,
`en--AU`, digit-bearing primaries, a second region), with the byte offset;
* `UnsupportedLanguageForm` — well-formed RFC 5646 outside the subset
(private use, singletons, variants, extended language subtags, 4–8 letter
primaries), never silently accepted;
* `LanguageNotCanonicalCase` — supported tags in non-canonical case
(`en-au`, `EN`, `zh-hans`), rejected rather than silently normalized.

Registry validity beyond RFC 5646 syntax is out of scope because the IANA
subtag registry is not a pinned data dependency. Length is bounded before
parsing (`max_language_bytes`, 64 on the facade; the subset's own maximum is
12 bytes).

*Title.* Non-empty, bounded (`max_title_bytes`, 2048 on the facade), and
every scalar must be an XML 1.0 character: C0 controls, DEL, U+FFFE, and
U+FFFF reject with `InvalidTitleScalar` at the exact byte offset (U+FFFD and
all other supplementary scalars pass through as canonical UTF-8). The same
single validation scan counts the `&`/`<`/`>` occurrences, so serialization
later knows its exact output size without rescanning.

*Timestamps.* `Metadata.TimestampInput` stays `Explicit(Str)` or
`Omitted`; the package never reads a clock. Explicit values accept exactly
the 20-byte canonical UTC form `YYYY-MM-DDThh:mm:ssZ` — no offsets, no
fractional seconds — with month/day ranges and the Gregorian leap rule
checked (`2024-02-29` accepted, `2023-02-29` rejected at offset 8). One
canonical input form means the emitted `xmp:CreateDate`/`xmp:ModifyDate`
need no normalization step.

Validation runs once, in `Pdf.build_plan` before any layout work on
the facade (so a rejected document costs no shaping or pagination) and at
the head of the kernel evidence pipeline; the returned `Facts` record —
including the escape counts — is what every later stage consumes.

[#contributor-metadata-output-intent-canonical-xmp-serialization]
== Canonical XMP serialization

`KernelXmp.Packet.build` writes a canonical UTF-8 packet. Namespace
declarations and properties follow URI and local-name order. The
`dc:language` bag has one validated language, and the `dc:title` Alt
has one `x-default` entry. Explicit times use canonical UTC; optional
omitted times leave no empty elements. Element text escapes `&`, `<`,
and `>`. Validation supplies exact byte limits and escape counts before
one buffer allocation. Metadata remains unfiltered.

[#contributor-metadata-output-intent-the-output-intent-and-the-packaged-profile]
== The output intent and the packaged profile

The packaged asset is `vendor/icc/sRGB2014.icc`, the ICC's official v2
sRGB profile, 3,024 bytes. The license, provenance, SHA-256, and ISO
15076-1 profile-ID self-check are recorded in `vendor/icc/NOTICE.md`
and `assets/provenance.json`. `scripts/build_srgb_profile.py` produces
`package/KernelSrgbProfile.roc`. The generated module pins size and
digest with an `expect`.

The metadata-bearing catalog's `/OutputIntents` array names one
`/GTS_PDFA1` dictionary. Its `/DestOutputProfile` references the canonical
three-component ICC stream, which is FlateDecode. Identical validated
profile bytes share that stream through their canonical resource
identity. The archival declaration is emitted in XMP by the selected
profile.

[#contributor-metadata-output-intent-independent-evidence]
== Independent evidence

`scripts/check_metadata.py` parses the original PDF and checks the
language, canonical packet, titles and times, output intent and profile
sharing, and exact ICC bytes. Test cases in `tests/spec.json` control
allocation and work for repeated metadata, omitted times, and located
malformed values. Use `scripts/check_metadata_renderers.py` with the
pinned external tools for independent rendering and metadata extraction.

See https://github.com/lukewilliamboswell/roc-pdf/blob/a6d1bde3028d51955b96af3ba1a183855a92cd2d/docs/contributors/performance/metadata-output-intent.md[the archived design and measurements].
