= Ordinary tables

Normalization keeps one dense table, row and cell store in authored order. Diagnostic paths identify the caption or the authored table section, row and cell. Semantic planning visits sections in authored reading order and checks their regular row/column rectangles. Every `TD` or `TH` retains its row and column span. Only accepted applicable headers become reciprocal `HeaderFor` and `Headers` facts. The combined attribute and relationship budget is charged before building the adjacency stores.

ISO 32000-2:2020+EC3 §14.8.4.8.3 and Table 371 govern table order, rectangular coverage and scope. `fuzz/TableHeaderModel.roc` independently rescans earlier row, column, and mixed scopes from authored grids. `scripts/check_structure_semantics.py` checks the emitted table trees, cells, spans and associations. The `tests/tables` fixture family includes the invoice x50/x500, empty cells x40/x400, and ruled grid x40/x400 scale pairs.

`KernelFacadeTables` resolves column widths before line selection using measured max-content and unbreakable widths. A cell's text width excludes its own padding. Two neighboring cells supply all of the inter-column spacing with their padding. The layout reserves decoration edges before committing frame occupancy, as described in xref:contributor-layout.adoc#contributor-table-paint-footprints[table paint footprints]. An empty cell has no text occurrence. Its row retains the ordinary geometry and structural cell.

Pagination consumes dense row-line units. A caption keeps with the first row. Repainted header cells reference existing shape and are emitted as `RepeatedHeader` artifacts with no pagination subtype. Their repaints are excluded from logical text, structure ownership and the once-emitted cluster accounting. Simple repeated headers use existing row geometry and need no per-page lead-band arena. Active continued containers keep explicit bands for paint geometry.
