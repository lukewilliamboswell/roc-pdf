= Test scheduling and fixture isolation

The driver plans one compiler validation per covered root. An evidence build
checks a fixture root, a test root runs expectations in its local closure,
and untested roots receive an explicit check. Validation and fixture builds
use hardware-aware concurrency. The current caps and inventory are in
`scripts/test.py` and `tests/spec.json`.

The driver writes its plan and metrics to a timestamped ignored log.
Use the xref:contributor-reference.adoc#contributor-fixture-grouping[fixture grouping contract]
to check that an optimization preserves the tested case and allocation
boundary. Preserve runtime source inputs and output snapshots when changing
how applications are grouped or scheduled.
