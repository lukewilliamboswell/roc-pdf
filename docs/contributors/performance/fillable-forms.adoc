[#contributor-fillable-forms]
= Fillable forms

The explicit `AccessibleForm` profile emits PDF/A-4 and PDF/UA-2 for labelled,
single-line text fields and independent checkboxes on fixed pages. The optional WTPDF accessibility declaration
uses the same form constraints. The writer checks the bytes it generates.
A reader owns subsequent user edits, appearances and saves.

[#contributor-fillable-forms-writer-checks]
== Writer checks

[cols="1,1",options="header"]
|===
|Requirement |Evidence
|ISO 32000-2:2020+EC3 §§12.5.5, 12.5.6.19, 12.7.2–12.7.4 and 12.7.5.3 |Each field has one editable text widget, a unique terminal field name, a plain initial value, and one normal appearance. The local and AcroForm default appearances use `Ftx` at 10 points. The decoder matches the appearance's text and resources to the authored value and checks the full 95-character ASCII range using the embedded program's cmap and horizontal metrics.
|ISO 19005-4:2020 §§6.2.10 and 6.3–6.4 |The form has an embedded editable font and explicit normal appearances. Widgets print and remain visible. The writer omits `NeedAppearances` and excludes actions, rich values and external programs from the policy.
|ISO 14289-2:2024 §§8.9.3.3, 8.10.1, 8.10.2 and 8.10.3.3, WTPDF 1.0 corresponding clauses, and ISO/TS 32005:2023 Table 5 |Every widget has one `Form` owner and OBJR via ParentTree. The direct `Lbl` child holds its decoded visible label, and `TU` carries the accessible field context. Ordered `Form` nodes and ordered page-local annotations preserve authored focus with `/Tabs /S`. The package admits only plain text and omits `RV`.
|===

The five field PDFs pass Arlington 1.30.2 and veraPDF 1.30.2 explicit `4` and
`ua2`. The WTPDF fixture also passes `wt1a`. The independent field decoder
rejects a different valid value in the appearance while Arlington and
veraPDF `4` and `ua2` accept the same mutation. It also rejects a read-only
flag and a changed field context. Poppler 26.07.0 at 96 dpi renders a blank
text interior and produces 296 nonwhite pixels in the matching interior of
the prefilled field.

The owning-facade model explores 518 states and 517 steps through depth
four with four witnesses. It checks authored label ownership, pages,
placement order and duplicate rejection for reordered text fields and
checkboxes, including a page boundary. A separate authored table compares
planned values and labels to the production field plan. The independent PDF decoder checks
values and appearances when an emitted fixture is read. Solve checks the
48-point geometry within the bounded page domain. The owning-facade
rejection fixture runs boundary widths, invalid values, duplicate IDs, the
128-field boundary, and incompatible profiles through both buffered and
chunked preparation. Omitted, explicit blank, and empty prefilled inputs
produce byte-identical files.

[#contributor-fillable-forms-checkbox-states]
== Checkbox states

ISO 32000-2:2020+EC3 §§12.5.5 and 12.7.5.2.3 connect each checkbox's
`V`, widget `AS` and named normal appearances. ISO 19005-4:2020 §§6.3–6.4
requires the state subdictionary for these button widgets. The writer
produces both appearances for every widget and shares two 22-point vector
streams throughout a document. The package uses the deterministic name
`Yes` for checked and `Off` for unchecked. The visible label and accessible
context identify the option independently. ISO 14289-2:2024 and WTPDF 1.0
§§8.9.3.3, 8.10.1, 8.10.2, 8.10.3.2.1 and 8.10.3.2.3 govern the label,
context and ownership. ISO/TS 32005:2023 Table 5 supplies the `Form` and
`Lbl` containment rules.

The checker decodes both streams, compares the selected state to the
authored choice, and confirms the label's ownership and mixed tab order.
Both unchecked authoring forms produce byte-identical output. Case
coverage includes duplicate IDs across types, layout endpoints with
one-millipoint negatives, the 128-field limit, and existing static
profiles. Solve checks placement of the box and label within their
266-point horizontal span.

All retained checkbox PDFs pass explicit veraPDF 1.30.2 `4` and `ua2`.
The declared WTPDF mixed PDF also passes `wt1a`. Arlington 1.30.2 reports
only `AnnotWidgetFieldBtnCheckbox-DA#7`, once per checkbox, because its
model requires a variable-text default appearance even for fully
specified vector checkboxes. The harness pins the exact rule and
occurrence count per path. ISO 32000-2:2020+EC3 §12.7.4.3 Table 228 applies
to variable-text fields. See https://github.com/pdf-association/pdf-issues/issues/323[PDF Association issue #323].

Mutating both `V` and `AS` to the wrong state or swapping the two
normal appearances preserves the external outcomes above. The project
checker detects both mutations. Its optional Poppler 26.07.0 rendering
check confirms the initial visible marks and their changes in the same
mutated files.

[#contributor-fillable-forms-allocation-and-work]
== Allocation and work

The field registry validates bounded UTF-8 strings and stably sorts
bounded IDs once. Widgets follow authored page order, so lowering and
checking scan the annotation plan without a field-by-page Cartesian pass.
Fixed page geometry shares checked span arithmetic. All appearances
reference one complete editable font program, shared with buffered and
chunked emission, and bounded label/value inputs keep field-local work
finite. The field rejects the 129th registered field before lowering.
