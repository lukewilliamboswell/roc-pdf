[#roc-font-choose-built-in-and-caller-fonts]
= Choose built-in and caller fonts

Ordinary `Pdf.to_bytes` documents use Inter for body text and headings. Inline
code and source blocks use Fira Code automatically; no files or registry setup
are required:

[source,roc]
----
import pdf.Pdf

example = Pdf.document({
    title: "A short report",
    language: "en-AU",
    contents: [
        Pdf.paragraph("Body text"),
        Pdf.rich_paragraph([Pdf.strong([Pdf.text("Strong")]), Pdf.emphasis([Pdf.text("Emphasis")])]),
        Pdf.source_block({ text: "answer = 42" }),
    ],
})
bytes = Pdf.to_bytes(example)?
----

To select Merriweather for serif typography, set the theme's family:

[source,roc]
----
options : Pdf.Options
options = { theme: { family: BuiltIn(Serif) } }
bytes = Pdf.to_bytes_with(example, options)?
----

A family choice selects one exact face for each requested style. Strong text
uses Bold, emphasis uses Italic, and nested strong/emphasis uses Bold Italic in
either nesting order. Titles and headings default to Bold. Code retains its
selected family while applying those style requests. Quote inherits its
surrounding family unless explicitly configured. Sizes, leading, colours and
spacing remain theme settings.

[cols="1,1,1,1",options="header"]
|===
| Family | Regular/Bold | Italic/Bold Italic | Command symbol U+2318
| Inter | Available | Available | Available in all four faces
| Merriweather | Available | Available | Missing in all four faces
| Fira Code | Available | Unavailable | Available in both faces
|===

The source character maps contain these per-face repertoires under the default shaping policy:

[cols="1,1,1",options="header"]
|===
| Faces | Mapped scalars per face | Convenience shaping
| Inter Regular/Bold | 2,852 | Single-scalar Latin
| Inter Italic/Bold Italic | 2,816 | Single-scalar Latin
| Merriweather Regular/Bold | 1,423 | Single-scalar Latin
| Merriweather Italic/Bold Italic | 1,422 | Single-scalar Latin
| Fira Code Regular/Bold | 1,586 | Single-scalar Latin
| Fira Code Italic/Bold Italic | Unavailable | Rejected
|===

The package ships ten unchanged upstream static font files. Measurement and
embedding use the same selected bytes, with
Regular at weight 400 and Bold at 700. No runtime variation axes or font
instancing are involved. The default shapes single-scalar Latin text. Glyph
coverage alone cannot enable a script or shape combining marks.
Italic repertoires can differ from upright ones. Source versions, hashes and
licences are recorded in the
https://github.com/lukewilliamboswell/roc-pdf/blob/main/vendor/fonts/roc-font/upstream-pins.json[font provenance].

Unavailable styles return located `text.style_unavailable` diagnostics naming
the selected family and style. Uncovered characters return located
`text.coverage_missing` diagnostics. For example, serif Command-K text fails,
and emphasis within default code fails because Fira Code has no genuine
italic. No font is substituted and no style is synthesised. These unsupported
requirements are tracked in https://github.com/lukewilliamboswell/roc-font/issues/13[roc-font's coverage/style issue]
and https://github.com/tonsky/FiraCode/issues/134[Fira Code's italic issue].

Caller fonts remain explicit. Register bytes with
`registry.register({ bytes, registration, limits })` and pass the returned
registry in `Pdf.Options.fonts`. A theme with `family: FromOptions` uses
`theme.face` as that caller family's Regular face. Requested Bold, Italic and
Bold Italic need an explicit family mapping or matching role override:

[source,roc]
----
family = {
    regular: regular.face,
    bold: Available(bold.face),
    italic: Available(italic.face),
    bold_italic: Available(bold_italic.face),
}
options : Pdf.Options
options = { fonts: Registered(registry), theme: { family: Registered(family) } }
----

Use `Unavailable` for a missing style. `theme.inline.strong.font`,
`theme.inline.emphasis.font` and `theme.inline.strong_emphasis.font` accept
exact `Face(id)` overrides. A combined request needs its combined face; an
upright or single-style face is never chosen implicitly. Inline family
choices use `Family(BuiltIn(Serif))` or `Family(Registered(family))`.

`theme.source_code` chooses the default source face, independently of the
body and inline code. A source block can override it with `face: Face(id)`
or `face: BuiltIn({ family: Mono, style: Bold })`. Explicit title, heading and
furniture `Face(id)` overrides continue to select registered faces.

`RocFont.register(registry, Font.ValidationLimits.default)` registers all ten
packaged faces once for applications that need reusable family handles;
`RocFont.theme(faces, base)` applies its sans/mono roles while preserving theme
sizes, colours, spacing and per-level heading overrides. The returned `sans`,
`serif` and `mono` records are family mappings. `RocFont.licenses` supplies all
three OFL notices; include them when distributing font assets. Distribution
pins and validation evidence live in https://github.com/lukewilliamboswell/roc-pdf/blob/main/docs/contributors/roc-font.md[the integration record].

Changing from the old restricted default or generated rc3 preset changes glyph
metrics, line breaks, pagination and PDF bytes. Review existing layouts after
upgrading. Wrap an existing explicit source handle in `Face(...)`, and add
family mappings or genuine role overrides where custom themes request styles.
Changing a dependency URL does not replace fonts an application registers itself.

[#inter-latin-shaping]
== Shape plain Latin paragraphs with Inter

Set `theme: { latin_shaping: InterLatin }` in `Pdf.Options` to use
Inter Regular kerning and default OpenType substitutions in plain
`Pdf.paragraph` text. Select the packaged Sans regular face or register
the byte-identical static Inter Regular that the package ships. The
shaping path covers printable ASCII and U+2192 in documents with English
language tags. It accepts one horizontal glyph per shaped cluster, including
ligatures, up to 16,384 scalars per paragraph. Paragraph colour affects paint
only. Rich inline spans, other faces and repertoires, ordered font policies,
fixed pages, and layout-dependent reference documents use their established
shaping paths. A failed Inter shape reports a diagnostic at the paragraph.

The two-character spelling `->` and the literal `→` can draw the same
glyph. Copying them preserves the authored spelling. Wrapping measures the
shaped advances. If a legal break crosses shaping context, preparation
shapes both sides independently before measuring. `NominalGlyphs` selects
the default metrics-only path.

See the https://github.com/lukewilliamboswell/roc-pdf/tree/main/examples/font-families[font specimen]
and https://github.com/lukewilliamboswell/roc-pdf/tree/main/examples/product-brief[wrapped paragraph example].

[#ordered-latin-and-han-coverage]
== Cover Latin and Han with an ordered font policy

Register the faces and pass their IDs in coverage order to
`registry.with_policy`. Set `theme.font_selection: Policy(policy)` and
carry the returned registry through `Pdf.Options.fonts`. Keep the language
of a Han phrase explicit with `Pdf.in_language`. The
https://github.com/lukewilliamboswell/roc-pdf/blob/main/examples/ordered-han/README.md[receiving handover example] uses packaged
Inter followed by a static Han subset in a paragraph, the running header,
and a table. Run its Latin-only variant to see a located missing-coverage
diagnostic.

[#hebrew-and-latin]
== Set unpointed Hebrew alongside Latin

Enable `theme.international_text: HebrewLatin` with `theme.font_selection:
Policy(policy)` and the registered fonts in `Pdf.Options.fonts`. Register
the packaged static Inter Regular and the exact static IBM Plex Sans Hebrew
Regular supplied with the xref:gallery.adoc#bilingual-invoice[bilingual invoice].
The order of the registered policy controls coverage for shared glyphs. Each
font is tracked by its bytes.

Author the text in reading order. Use `Pdf.in_language("he", ...)` for
Hebrew and identify other meaningful changes, such as French within English
payment instructions. The first strong character in each paragraph sets its
base direction. The composer resolves each line after wrapping and retains
the logical text and ownership of styled spans and table cells. When an
authored text block has a right-to-left base, its structure element declares
`RlTb` writing mode. Other blocks use the PDF default `LrTb`.

The supported repertoire covers unpointed Hebrew letters, printable ASCII,
Latin-1 letters and selected punctuation. Vowel points, bidi controls and
other scripts give a located error. The option applies to ordinary
single-column flow and table cells. It excludes fixed-page placement, columns,
source blocks, layout-dependent references and explicit role face selection.

[#arabic-and-latin]
== Set unpointed Arabic alongside Latin

Enable `theme.international_text: ArabicLatin` with an ordered font policy
over the packaged static Inter Regular and the exact static IBM Plex Sans
Arabic Regular supplied with the xref:gallery.adoc#arabic-invoice[Arabic
supplier invoice]. Use `Pdf.in_language("ar", ...)` for Arabic text. Basic
unpointed Arabic letters, Arabic-Indic digits and selected Arabic
punctuation use the horizontal Arabic OpenType shaper. Its joined glyphs
and lam-alef ligatures preserve the authored text.

Place each Arabic word in one inline span. Vowel marks, Arabic presentation
forms, and explicit joining controls give a located error. The same flow,
font-selection and layout limits as the Hebrew and Latin mode apply.

[#hindi-and-latin]
== Set Hindi alongside Latin

Enable `theme.international_text: HindiLatin` with an ordered font policy
over the packaged static Inter Regular and the exact IBM Plex Sans
Devanagari Regular supplied with the xref:gallery.adoc#hindi-statement[Hindi
statement]. Devanagari text must have an effective `hi` language tag.
Use `Pdf.in_language("hi", ...)` inside a document with another language.
Keep each grapheme within one authored inline.
