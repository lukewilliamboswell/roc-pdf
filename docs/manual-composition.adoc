[#manual-composition-composing-a-technical-manual]
= Composing a technical manual

Use ordinary `Pdf` blocks to combine chapter text, numbered instructions,
tables, callouts and diagrams in one document. The
https://github.com/lukewilliamboswell/roc-pdf/blob/main/examples/operations-handbook/README.md[runnable on-call handbook] combines
authored contents, chapter scopes, restarted appendix labels and a
numbered rollback item that continues across pages.

[#manual-composition-print-page-numbers-in-a-table-of-contents]
[#generate-contents-from-headings]
== Generate contents from headings

Place `Pdf.generated_contents` at the top level where the contents should
start. It collects anchored headings in authoring order. Heading names
identify destinations even when their visible titles repeat.

[source,roc]
----
Pdf.generated_contents({
    scope: Under("procedures"),
    depth: 2,
    leader: Dots,
    page_width: 36,
    numbering: PageLabel,
    overrides: [{ target: "second-check", title: "Follow-up checks" }],
})
----

Use `WholeDocument` for the whole heading sequence. With `Under(name)`,
the named heading identifies the start and is excluded. Collection stops at
the next heading at the same or a shallower level. `depth` counts from the
document or selected heading. Plain headings still determine scope, but
entries require `Pdf.destination_heading` to provide a target. An override
must name a selected target. Empty selection, a missing scope, and an
invalid override report `document.generated_contents` at the request.

Links, end-aligned page fields, and artifact leaders use the same layout
as authored `Pdf.contents_entry`. Choose a fixed `page_width` wide enough
for the labels. Generated entries may take several pages, and the printed
labels refer to the final heading placements. Keep headings and overrides
meaningful in isolation.

https://github.com/lukewilliamboswell/roc-pdf/blob/main/examples/operations-handbook/README.md[Run the generated handbook] to see the first chapter move from page 2 to
page 3 while its link and printed number follow it.


== Print page numbers in a table of contents

Give each chapter a named destination with `Pdf.destination_heading`, then
use `Pdf.contents_entry` for a linked title and a page number at a common right
edge. Set `indent` for ancestry and `leader: Dots` for decorative subsection
leaders. Titles wrap and may continue across pages; the number stays beside
the final title line. References reserve a fixed width; choose enough space
for the longest page number or configured label.

See xref:destination-page-references.adoc#destination-page-references-destination-page-references[Destination page references] for a complete
example, numbering options and overflow diagnostics. You author the contents
entries yourself; roc-pdf resolves their page values.

[#manual-composition-give-chapters-their-own-headers-and-opening-pages]
== Give chapters their own headers and opening pages

Wrap a chapter's blocks in `Pdf.page_scope`. Set
`running_label: Label("Installation")` and put `Pdf.running_label` in header
or footer furniture. Use `Pdf.reserved_width` to reserve space for that label.

The scope's `page_templates` property accepts separate `opening` and
`continuation` templates. This lets you use a quiet chapter opener and running
headers on later pages. Scopes start and end on full body-page boundaries and
cannot nest. Author chapter headings, destinations and outlines explicitly.

See xref:authoring.adoc#authoring-chapter-aware-page-scopes[Chapter-aware page scopes] for
template options, reset behavior and layout limits.

[#manual-composition-keep-rich-content-inside-numbered-instructions]
== Keep rich content inside numbered instructions

A `Pdf.list_item` starts with a paragraph. After it, include rich paragraphs,
source blocks, figures, tables, callouts or nested lists. These remain part of
the same numbered item when it continues across pages; the item label prints
once. Lists nest at most four levels.

Use `Pdf.source_block` for code with preserved whitespace. Figures stay with
their captions, and tables use their normal row-continuation and repeated-header
policies. All children use the available item width, including list indentation
and any enclosing callout padding. The xref:authoring.adoc#authoring-lists[authoring guide] includes
list, source, figure and table examples.

[#manual-composition-continue-boxed-notes-across-pages]
== Continue boxed notes across pages

Use `Pdf.callout` for a box whose height follows its content. By default,
`fragmentation: Lines` allows continuation at supported child boundaries;
each page fragment repeats the panel and padding. Set `Unsplittable` when the
whole note must fit on one page.

Callouts accept paragraphs, lists, source blocks, figures, ordinary tables and
nested callouts. They share a maximum nesting depth of 16 with semantic
containers. Content that cannot fit returns a located diagnostic. See the
xref:authoring.adoc#authoring-callouts[callout example and limits].

[#manual-composition-add-vector-diagrams]
== Add vector diagrams

Place a drawing with `Pdf.figure`, supplying alternative text and an optional
caption. The https://github.com/lukewilliamboswell/roc-pdf/blob/main/examples/vector-diagrams/README.md[prepared vector-diagram example]
shows how to prepare a constrained Mermaid/SVG flowchart as public Roc drawing
commands with searchable text.

Preparation is separate from PDF generation. The example rejects embedded HTML
labels and unsupported SVG features; it does not provide general SVG or HTML
rendering. Its accepted profile, font requirements and preparation commands
are documented with the example.
