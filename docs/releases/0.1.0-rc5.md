# roc-pdf 0.1.0-rc5

This candidate lets external syntax highlighters colour preformatted source text through `Pdf.source_block`, while roc-pdf retains source normalization, shaping, measured wrapping, searchable text and page continuation.

## Changes since rc4

- Add optional `foregrounds: [{ start, end, color }]` with zero-based, half-open byte offsets into the original UTF-8 `text`. Unstyled gaps retain the block foreground.
- Map accepted ranges through CRLF normalization and tab expansion. A covered tab colours every expanded space; CRLF is indivisible. Range endpoints must be extended-grapheme boundaries.
- Apply colour after shaping and pagination, preserving positions, wrapping, page breaks, `P > Code` semantics and canonical ActualText. Colour spans can cross visual lines and page fragments; panel backgrounds remain artifacts. Emitted glyph positions are identical with and without colour, including for proportional faces.
- Reject reversed, empty, overlapping, unsorted, out-of-bounds, invalid-boundary and unsupported-colour ranges with located diagnostics. Retained foreground ranges are bounded at 100,000 across the document.
- Keep tokenization, language categories and theme selection in caller code. No lexer, language dependency, font switching or per-token semantic nodes are introduced.

Existing calls without foregrounds retain their behavior. The default remains static PDF/A-4 (`Archive`); PDF/UA-2 is not claimed and `AccessibleArchive` remains unavailable. Unsupported requests return typed errors without fallback or downgrade.

## Using the candidate

Use Roc `nightly-2026-10-14-38a3029`. Add the package to your application header:

```roc
pdf: "https://github.com/lukewilliamboswell/roc-pdf/releases/download/0.1.0-rc5/ANqp54fCvoErcZijX5Dr2cZj5G7ZzW6DYNLPj5GJBz4N.tar.zst",
```

Bundle SHA-256: `bd7b9d96ec3160e923b165d003ed2d8d9f4e25fd8b276b627b7eb2e1a4c8cf60`.

The public `Pdf` facade remains the primary API.

```roc
Pdf.source_block({
    text: "app [main!] {}\n",
    face: mono.face,
    foregrounds: [
        { start: 0, end: 3, color: "#8000c0" },
        { start: 5, end: 10, color: "#0050d0" },
    ],
})
```

MuPDF 1.28.2's default text extractor repeats parent Code ActualText across marked-content pieces, including uncoloured controls. PDFBox and MuPDF's explicit glyph/ToUnicode extraction mode report each character once, in order. This is a reader limitation; the source semantics are unchanged.

See the [authoring guide](https://github.com/lukewilliamboswell/roc-pdf/blob/7cdd4d12f78f3696046a0e3ee7bf3150e6d38dc4/docs/authoring.md).
