# roc-pdf 0.3.0

This release changes the built-in typography and several public call signatures.
It remains a generation-only PDF 2.0 package with static PDF/A-4 output by
default. These changes do not add a PDF/UA-2 or production-readiness claim.

Use the tested package bundle:

```roc
pdf: "{package-url}",
```

Bundle SHA-256: `{bundle-sha256}`.

The package compiler remains `nightly-2026-10-28-bad769b`.

## Built-in typography

Ordinary documents use Inter, explicit serif typography uses Merriweather,
and inline/source code uses Fira Code without application-managed assets.
Inter and Merriweather supply genuine Regular, Bold, Italic and Bold Italic
faces; Fira Code supplies Regular and Bold. The static files come from
roc-font 0.1.0-rc4 with their original licences and pinned provenance.

Missing glyphs, unsupported scripts and unavailable requested styles fail
before PDF bytes are returned. Merriweather does not contain the Command
symbol (U+2318), and Fira Code has no genuine italic face. No automatic
font substitution or synthetic styling is performed.

The changed metrics can alter line breaks, page breaks and PDF bytes. Review
existing document layouts after upgrading. Custom families must explicitly
supply requested style faces or matching role overrides. Source blocks with
an explicit face now wrap the handle in `Face(...)`; omitted faces use the
theme's source-code selection.

## Named arguments

Links, destinations, expansions, reserved widths, report-budget preparation,
drawing operations, geometry/ranges and advanced authoring now name their
argument roles. Font registration names `bytes`, `registration` and `limits`.
See [the migration guide](../migrating-named-arguments.md) for replacement
calls. Consuming builders retain their receiver.

## Diagnostics and examples

Pipeline diagnostics classify typed causes while preserving stable feature
identities and useful stage context. Preparation reports reject inconsistent
figure facts instead of inventing scales or omitting figure obligations.
The prepared-vector example accepts explicit font-validation limits and
preserves meaningful registration errors.

## Documentation

The user manual is available as HTML, PDF and Markdown alongside the existing
API reference. Release archives include the tested package, examples and
documentation. Default-branch documentation is labelled unreleased.
