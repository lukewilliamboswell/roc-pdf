# roc-pdf 0.1.0-rc3 (draft)

This candidate closes Gate 5, static PDF/A-4, and advances the default
profile.

Highlights:

- `Pdf.Options.default` selects `Archive`, which claims `Pdf20 + StaticPdfA4`.
  `Pdf.to_bytes`, `Pdf.to_bytes_with(document, Pdf.Options.default)`, and the
  chunked forms now produce static PDF/A-4 output.
- The canonical XMP packet declares the PDF/A Identification schema
  (`pdfaid:part` 4, `pdfaid:rev` 2020) only for a validated claim. `Standard`
  output never declares it.
- A closed static whitelist is enforced by profile validation over prepared
  text facts and lowered-plan validation over every sealed plan, before any
  byte exists.
- A document that cannot meet the claim returns `InvalidDocument` with the
  new `Conformance.DiagnosticCode` `ProfileRequirementViolated`, the ledger
  requirement id, and the ISO 19005-4 clause. It never falls back to
  `Standard`.
- Every Archive fixture and gallery document passes the pinned veraPDF 1.30.2
  PDF/A-4 profile with zero failed checks. The upstream veraPDF PDF/A-4 corpus
  returns its expected verdicts, and three renderers draw Archive output
  identically to its `Standard` twin.

## Migrating

- **Bytes change.** Default output grows by exactly 112 bytes per document
  (the identification in the metadata stream). Rendering is unchanged.
  Snapshot tests that pin default bytes must be regenerated.
- **Keeping plain PDF 2.0.** Opt out explicitly:
  `Pdf.Options.with_profile(Pdf.Options.default, Pdf.Profile.Standard)`.
  `Standard` is never selected automatically.
- **Exhaustive matches.** `Conformance.DiagnosticCode` gains
  `ProfileRequirementViolated`. Exhaustive matches over that closed union need
  a new branch.
- **`profile.archive` feature code.** `Archive` no longer reports
  `FeatureUnavailable` `profile.archive`. The feature code is still used for
  `ProfileRequirementViolated` diagnostics. `AccessibleArchive` still reports
  `profile.accessible_archive`.

## Semantic containers (Gate 6 semantic foundation)

- **API change.** `Pdf.section` was a `Str -> Document.Block` placeholder that
  reported `semantics.containers`. It is now
  `Pdf.section : List(Document.Block) -> Document.Block` and produces a `Sect`
  structure element around its children. `Pdf.part` (`Part`) and
  `Pdf.division` (`Div`) are new with the same shape. Replace
  `Pdf.section("summary text")` with `Pdf.section([...blocks])`.
- **Exhaustive matches.** `Document.Block` gains the `Container` alternative,
  and the retired `SemanticContainers` alternative is removed from
  `Document.Feature`; `semantics.containers` is no longer reported.
- **New diagnostics.** `semantics.container_depth` (`BudgetExceeded`, more
  than 16 nested containers) and `semantics.empty_container`
  (`InvalidRelationship`) carry the container's block path in `details`.
- **Bytes change.** Every tagged document lowered with metadata gains
  `/ViewerPreferences << /DisplayDocTitle true >>` in its catalog: exactly 47
  more bytes, and a different trailer `/ID`. Rendering is unchanged.
- **Advanced types.** `Document.NormalizedBlock` gains `parent`, and
  `Document.NormalizedAuthoring` gains the dense `groups` arena
  (`Document.NormalizedGroup`). The kernel semantic subset now admits the
  grouping, inline, and table roles, typed element identifiers, Table and List
  attributes, and `HeaderFor`, `CaptionFor`, and `LabelFor` relations, each
  validated against ISO/TS 32005 Table 5 and lowered as `/ID`, `/IDTree`, `/A`,
  `/Lang`, `/Alt`, `/E`, and `/ActualText`.

See the [semantic-foundation record](../performance/semantic-foundation.md).

## Rich inline content (Gate 6 rich-inline slice)

- **API change.** `Pdf.rich_paragraph` was a `Str -> Document.Block`
  placeholder that reported `semantics.rich_inline`. It is now
  `Pdf.rich_paragraph : List(Pdf.Inline) -> Document.Block` and produces a `P`
  around its inline structure. Replace `Pdf.rich_paragraph("text")` with
  `Pdf.rich_paragraph([Pdf.text("text")])`.
- **New constructors.** `Pdf.Inline` with `Pdf.text`, `Pdf.emphasis` (`Em`),
  `Pdf.strong` (`Strong`), `Pdf.code` (`Code`), `Pdf.quote` (`Quote`),
  `Pdf.inline_link` and `Pdf.inline_internal_link` (`Link` plus a link
  annotation per page painted), `Pdf.in_language` (`Span` with `/Lang`), and
  `Pdf.expansion` (`Span` with `/E`). Lines break across inline boundaries.
- **Theme.** `Theme.with_emphasis_color`, `with_strong_color`,
  `with_code_color`, and `with_quote_color` color inline roles; unthemed roles
  paint like their paragraph. `Theme.with_text_color` returns them to that
  inherited color. Inline roles never change face, size, or leading.
- **New diagnostics.** `semantics.inline_empty`, `semantics.inline_depth`
  (more than 8 nested inline elements), `semantics.link_uri`,
  `semantics.nested_link`, `semantics.link_text_empty`, and
  `semantics.language_tag`, plus `text.unsupported_script` and
  `text.unsupported_cluster` for text inside a rich paragraph. Each carries
  the inline's path, such as `contents[2].inlines[1]`, in `details`.
- **Exhaustive matches.** `Document.Block` gains `RichParagraph`, and the
  retired `RichInline` and `NestedLanguage` alternatives are removed from
  `Document.Feature`; `semantics.rich_inline` and `semantics.nested_language`
  are no longer reported.
- **Bytes change.** A link annotation's quadrilateral and rectangle heights
  now use the painted run's own leading. The previous lowering read the style
  of an unrelated run, which changed link boxes only when a multi-line block
  preceded the link and its leading differed; three archived navigation
  snapshots change by one rectangle and quadrilateral. Rendering is
  unchanged.
- **Advanced types.** `Document.NormalizedAuthoring` gains the dense `inlines`
  arena (`Document.NormalizedInline`), and `Document.NormalizedBlockKind`
  gains `RichParagraph(Document.NormalizedRich)`.

See the [rich-inline record](../performance/rich-inline.md).

## Lists, breaks, keeps, and layout policies (Gate 6 layout-policies slice)

- **New constructors.** `Pdf.bullet_list`, `Pdf.numbered_list` (with
  `Pdf.NumberStyle`: `Decimal`, `LowerAlpha`, `UpperAlpha`, `LowerRoman`,
  `UpperRoman`), and `Pdf.list_item` build `L > LI > (Lbl, LBody)` lists whose
  items hold paragraphs, rich paragraphs, and nested lists. `Pdf.page_break`,
  `Pdf.spacer`, `Pdf.keep_together`, `Pdf.keep_with_next` (with `Pdf.Keep`:
  `Required`, `Preferred`), and the inline `Pdf.line_break` control the flow
  and produce no structure.
- **Layout policy.** Pagination separates mandatory constraints (unsplittable
  headings, titles, figures, and keep-together groups; required keeps;
  explicit breaks) from ranked preferences (R1 heading keeps, R2 preferred
  keeps, R4 orphan and R5 widow minimums). Each page takes the latest break
  with the best preference vector; a preference no legal break satisfies is
  relaxed and recorded instead of failing. Documents whose pagination
  previously succeeded are paginated identically; documents that previously
  failed only because a heading chain, orphan, or widow minimum could not be
  met now succeed with a recorded relaxation.
- **New diagnostics.** `Conformance.DiagnosticCode` gains
  `LayoutConstraintViolated`, used by `layout.keep_conflict`,
  `layout.oversize_block`, `layout.keep_empty`, `layout.page_break_position`,
  `layout.spacer_negative`, and `layout.list_label_width`; figures taller
  than a page report `document.figure_oversize`. Lists add
  `semantics.list_empty`, `semantics.list_item_empty`,
  `semantics.list_item_content`, `semantics.list_depth`, and
  `semantics.list_numbering`, and line breaks
  `semantics.line_break_position`. Each carries the authored path of every
  participating source in `details`; these failures previously surfaced, if
  at all, as `UnsupportedAuthoringContent`.
- **Exhaustive matches.** `Conformance.DiagnosticCode` gains
  `LayoutConstraintViolated`; `Document.Block` gains `KeepTogether`,
  `KeepWithNext`, `ListBlock`, `PageBreak`, and `Spacer`; `Document.Inline`
  gains `LineBreak`.
- **Bytes change.** Every list, including `Pdf.bullets`, now declares its
  `ListNumbering` (`/A << /ListNumbering /Disc /O /List >>` for bullets), which
  PDF/UA-2 requires of labelled lists. Rendering is unchanged.
- **Fixes.** A document longer than 32 pages failed preparation with an
  internal error, because a multi-level page tree node referenced its parent
  from the wrong object builder; it now lowers. The facade's object-store
  budget for name bytes rises to 1 MiB, since every structure element and
  attribute dictionary interns its names.
- **Advanced types.** `Document.NormalizedGroup.kind` is now
  `Document.NormalizedGroupKind` (containers, lists, list items, and keeps),
  and `Document.NormalizedAuthoring` gains `lists`, `line_breaks`,
  `page_breaks`, and `spacers`.

See the [layout-policies record](../performance/layout-policies.md).

## Boundaries

PDF/UA-2 and the combined `AccessibleArchive` claim remain unavailable. The
advanced `Encode` boundary has no profile input and continues to emit
`Standard` output.

ISO 19005-4 requirements that the pinned validator profile does not encode are
derived from public information. They are recorded as pending confirmation
against the licensed standard text before the combined claim.

See the [slice record](../performance/static-pdfa4.md) and the
[authoring guide](../authoring.md).
