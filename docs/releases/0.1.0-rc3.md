# roc-pdf 0.1.0-rc3 (draft)

This candidate closes Gate 5, static PDF/A-4, and advances the default
profile.

Highlights:

- `Pdf.Options.default` selects `Archive`, which claims `Pdf20 + StaticPdfA4`.
  `Pdf.to_bytes`, `Pdf.to_bytes_with(document, Pdf.Options.default)`, and the
  chunked forms now produce static PDF/A-4 output.
- The canonical XMP packet declares the PDF/A Identification schema
  (`pdfaid:part` 4, `pdfaid:rev` 2020) only for a validated claim. `Standard`
  output never declares it.
- A closed static whitelist is enforced by profile validation over prepared
  text facts and lowered-plan validation over every sealed plan, before any
  byte exists.
- A document that cannot meet the claim returns `InvalidDocument` with the
  new `Conformance.DiagnosticCode` `ProfileRequirementViolated`, the ledger
  requirement id, and the ISO 19005-4 clause. It never falls back to
  `Standard`.
- Every Archive fixture and gallery document passes the pinned veraPDF 1.30.2
  PDF/A-4 profile with zero failed checks. The upstream veraPDF PDF/A-4 corpus
  returns its expected verdicts, and three renderers draw Archive output
  identically to its `Standard` twin.

## Migrating

- **Bytes change.** Default output grows by exactly 112 bytes per document
  (the identification in the metadata stream). Rendering is unchanged.
  Snapshot tests that pin default bytes must be regenerated.
- **Keeping plain PDF 2.0.** Opt out explicitly:
  `Pdf.Options.with_profile(Pdf.Options.default, Pdf.Profile.Standard)`.
  `Standard` is never selected automatically.
- **Exhaustive matches.** `Conformance.DiagnosticCode` gains
  `ProfileRequirementViolated`. Exhaustive matches over that closed union need
  a new branch.
- **`profile.archive` feature code.** `Archive` no longer reports
  `FeatureUnavailable` `profile.archive`. The feature code is still used for
  `ProfileRequirementViolated` diagnostics. `AccessibleArchive` still reports
  `profile.accessible_archive`.

## Boundaries

PDF/UA-2 and the combined `AccessibleArchive` claim remain unavailable. The
advanced `Encode` boundary has no profile input and continues to emit
`Standard` output.

ISO 19005-4 requirements that the pinned validator profile does not encode are
derived from public information. They are recorded as pending confirmation
against the licensed standard text before the combined claim.
