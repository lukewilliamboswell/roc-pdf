# roc-pdf 0.1.0

roc-pdf is a pure Roc package for generating deterministic PDF 2.0 documents.
It does not read, edit or repair PDFs, and it has no native dependencies.
0.1.0 is the first release after the 0.1.0 release candidates. It makes
`Balanced` compression the default, adds a `compression` option, and
substantially reduces allocation during generation.

## Using the release

Use Roc [`nightly-2026-10-23-18478ff`](https://github.com/roc-lang/nightlies/releases/tag/nightly-2026-10-23-18478ff). Add the
package to your application header:

```roc
pdf: "https://github.com/lukewilliamboswell/roc-pdf/releases/download/0.1.0/FtvjgqwbGNGsm97hoN8kayCX3QacEwMbJo6aPZd7LPEi.tar.zst",
```

Bundle SHA-256: `d0945e287568f87c79e72beb4777c2ef1403d4eb9a7a5dfa412a93371dac958f`.

Import `pdf.Pdf` and start with the [authoring guide](../authoring.md) and the
[example gallery](../../examples/README.md). Every gallery example is a
complete application that works against the released bundle once its `pdf`
dependency names the URL above.

## What 0.1.0 supports

The `Pdf` facade is the primary API: build a document from records and
constructors, then call `Pdf.to_bytes`.

- **Business documents.** Titles, headings, paragraphs, rich inline text
  (emphasis, strong, code, quotes, links, language spans and expansions),
  bulleted and numbered lists, sections, tables with captions, column spans,
  footers and repeated headers, figures with required alternative text,
  callouts and measured custom blocks. The gallery includes a multi-page
  invoice, a business report and a business letter.
- **Pagination.** Automatic page breaking with explicit line and page breaks,
  spacers, and required or preferred keeps. Tables continue across pages;
  `KeepRows` and `SplitRows` choose how rows break.
- **Page furniture.** First-page and continuation templates with header,
  footer and letterhead regions, page and total-page numbers, page labels, and
  independent furniture typography.
- **Technical manuals.** Printed destination page references, chapter scopes
  with their own opening pages and running labels, numbered instructions that
  keep code, figures and tables together across pages, and callouts that
  continue across pages. See [composing a technical manual](../manual-composition.md).
- **Source listings.** `Pdf.source_block` preserves indentation and blank
  lines, uses its own monospace face, continues across pages, and accepts
  foreground colour ranges from an external syntax highlighter.
- **Images and drawings.** Typed JPEG and packed-raster images, and solid
  vector drawings with grouped commands and searchable labels.
- **Fonts and text.** The packaged face, or caller-registered TrueType faces
  selected per role or through an ordered multi-face policy that picks a face
  per character cluster by coverage. Text remains searchable and selectable.
- **Navigation and metadata.** Named destinations, internal and external
  links, outlines, page labels, and document metadata with explicit
  timestamps.
- **Archival output.** The default `Archive` profile writes tagged PDF 2.0
  that claims static PDF/A-4. Select `Standard` for plain PDF 2.0.
- **Output control.** Prepare a document once, then write buffered bytes or
  chunks. Both produce identical bytes. A preparation report lists pages,
  layout decisions and checks that only the author can make.

Output is deterministic: the same inputs, options and package version produce
the same bytes. A request the package cannot meet returns a typed, located
error with no output. The package never falls back to a weaker profile,
substitutes fonts, or converts text to outlines or images.

See the [supported features table](../authoring.md#supported-features) for the
complete list.

## Changes since rc6

- **Compression choice.** The new `Pdf.Options.compression` field selects
  `Balanced` (the default), `Smallest` or `Fastest`. `Balanced` makes the
  compression step of a large report roughly ten times faster than before,
  and files are a few percent larger. `Smallest` writes the same bytes as
  rc6. `Fastest` writes larger files in the least time. Every choice writes
  the same pages, text, structure and conformance claims.
- **Lower allocation.** Preparing and writing documents allocates far less.
  Across the package's test documents, allocations fell by about 85% and
  requested memory by about a third. Content and structure are unchanged.
- **Toolchain.** The package requires Roc
  `nightly-2026-10-23-18478ff` (rc6 required
  `nightly-2026-10-14-38a3029`). It now depends on `unicode` 4.3.0 and
  `roc-deflate` 0.4.0-rc4. Roc fetches both automatically.

## Upgrading from rc6

Existing calls compile unchanged. Install the Roc nightly named above and
update the package URL.

Default output bytes change because `Balanced` is now the default. Text,
structure, metadata and document identifiers are unchanged. If you compare
output with stored files or checksums, either update the expected bytes or
pass `Smallest` to keep the rc6 bytes:

```roc
bytes = Pdf.to_bytes_with(document, { compression: Smallest })?
```

The compression choice is fixed when a document is prepared, so
`Pdf.to_bytes_prepared` and `Pdf.to_chunks_prepared` write the same bytes as
`Pdf.to_bytes_with` for the same options.

## Upgrading from earlier release candidates

Apply each release's notes in order:

- From rc1: follow [migrating to rc2](../migrating-to-rc2.md).
- From rc2: see the [rc3 notes](0.1.0-rc3.md). `Archive` became the
  default profile. Theme and option setters were replaced by records with
  defaults. `Pdf.section` and `Pdf.rich_paragraph` take lists.
  `Pdf.page_header` and `Pdf.page_footer` were replaced by
  `page_templates`. `Text.Run.occurrence` became `Text.Run.unicode`.
- From rc3: see the [rc4 notes](0.1.0-rc4.md). These add source blocks and
  independent furniture typography. Existing output is preserved.
- From rc4: see the [rc5 notes](0.1.0-rc5.md). Source-block foreground
  ranges are optional.
- From rc5: see the [rc6 notes](0.1.0-rc6.md). Exhaustive matches over
  `Document.Block`, `Document.Inline` and `Pdf.ReportOutcome` must handle
  the new manual-composition alternatives. Corrected table positioning can
  change page breaks.

Each step can change output bytes. Review expected PDFs after upgrading.

## Known limits

- PDF/UA-2 is not claimed. `AccessibleArchive` returns
  `profile.accessible_archive`. Structure tags alone do not make a document
  accessible: alternative text, reading order and language remain author
  responsibilities, and the preparation report lists those checks.
- The static PDF/A-4 claim is validated with veraPDF's PDF/A-4 profile.
  Requirements that profile does not encode are enforced by construction from
  public descriptions of ISO 19005-4. They have not yet been confirmed against
  the licensed standard text.
- The advanced `Encode` boundary writes `Standard` output only.
- Fixed pages, multiple columns, floats, footnotes, row spans and complex
  tables are unavailable and return a feature diagnostic. Clip, opacity,
  soft-mask and non-solid paint in flow drawings are also unavailable.
- Custom blocks do not split across pages. Page scopes cannot nest and start
  on a fresh page. Every page in a document uses one page size.
- Automatic hyphenation is not supported. The facade shapes a declared set of
  scripts; right-to-left and case-transformed output are available only
  through the advanced modules.
- Only TrueType-flavoured fonts are accepted. The package does not synthesize
  bold or italic.
- Reading, editing, repairing, signing and encrypting PDFs, interactive
  forms, attachments and JavaScript are out of scope.
- Roc has not reached 1.0. Each roc-pdf release supports exactly one Roc
  nightly; use the nightly named above.
