# Output size

This record covers the work that removed the removable bytes found by the
2026-09-30 size audit, which compared roc-pdf with Typst 0.15.1 on the same
content. Both sides write PDF 2.0, claim PDF/A-4, and are tagged. Each step
below is one or more commits. Every step records its byte budget, the
conformance basis for what it removed, the visual evidence, and the class of
allocation and work movement it caused.

Byte budgets come from the audit's `budget.py`, which attributes every file
byte to one category from qpdf's object model and the xref offsets. "Before"
is the snapshot before the step, "After" the snapshot after it.

## Evidence method

- **Rendering.** Every tracked PDF (259 files, 4,952 pages) is rendered with
  the pinned MuPDF 1.28.2 `mutool draw -r 100` before and after the step and
  compared pixel by pixel. `tests/forms/forms_deep_64.pdf` is excluded from
  the count: MuPDF refuses its 64-deep form nesting ("exception stack
  overflow") both before and after, which is its documented nesting limit
  rather than a change. Gallery previews are re-rendered with `pdftoppm -r
  96`, as `examples/README.md` records.
- **Structure.** Every case's registered validators run on the new snapshot,
  every checker self-test runs, and the external lanes (veraPDF PDF/A-4,
  Arlington, PDFBox structure extraction) run on every snapshot and gallery
  PDF.
- **Allocation.** Baselines are measured from a cold `XDG_CACHE_HOME` with the
  pinned compiler, and every class of movement is explained below.

## 1. Compressed font programs, ToUnicode CMaps, and ICC profiles

### What changed

- `FontFile2` subset programs and `ToUnicode` CMaps are FlateDecode streams
  (`KernelPdfFont`). They were unfiltered although their payloads were
  generated bytes.
- The CIDFontType2 descendant declares `/CIDToGIDMap /Identity` instead of
  carrying an identity map stream. Font planning already guaranteed and
  validated CID = subset glyph ID for every retained glyph; the lowering now
  proves that fact (`validate_identity_cid_map`) instead of serializing it.
  Each Type 0 bundle drops from nine objects to seven (the map stream and its
  length object).
- ICC profile streams (the output-intent profile and every `/ICCBased`
  profile) are FlateDecode. Their payload kind changes from
  `UnchangedResource` to `Generated`, because the emitted bytes are no longer
  the resource's own bytes, so they are no longer eligible for zero-copy
  chunk sharing. JPEG data is still shared unchanged.
- The XMP metadata stream stays unfiltered.

### Conformance basis

- ISO 32000-2 9.7.4, Table 115: a CIDFontType2 `CIDToGIDMap` is "a stream
  mapping from CIDs to glyph indices or the name Identity". veraPDF rule
  6.2.10.3.2-1 ("the CIDFont dictionary shall contain a CIDToGIDMap entry
  that shall be a stream ... or the name Identity") is the same requirement,
  and the package's own `KernelPdfA4` check only requires the entry to exist.
- Font program, CMap, and ICC streams may use any standard filter in PDF 2.0.
  PDF/A-4 restricts only the filter set: veraPDF rule 6.1.6.2-1 allows every
  ISO 32000-2 Table 6 filter except LZWDecode, and the package's narrower
  `StreamFilters` requirement is "only FlateDecode and DCTDecode".
- The metadata stream stays unfiltered: `KernelPdfA4` rejects a filtered
  metadata stream (ledger requirement `MetadataStream`), which the size audit
  confirmed.

### Rendering

All 4,951 comparable pages are pixel-identical at 100 dpi, and every gallery
preview is byte-identical after re-rendering.

### Allocation and work

- **Allocations** rise by a few events per newly compressed stream: each
  DEFLATE stream allocates its match table, its block buffer, and its chunk.
  The font-leaf scale pair stays linear: +78 allocations for eight distinct
  subsets and +638 for 64.
- **Allocated bytes** rise by about 0.52 MB per newly compressed stream. That
  is `KernelDeflate`'s fixed `hash_size + window_size` table of 65,536 `U64`
  slots, which it allocates per block whatever the input length. A 380-byte
  ToUnicode CMap pays the same 512 KiB as a 64 KiB content stream. The cost is
  linear in the number of streams (eight subsets: +16.9 MB; 64 subsets:
  +133 MB), so it is not the quadratic copying the ceiling exists to catch.
  The compressor is being replaced (step 4), and a table sized by
  `min(input, window)` removes most of it.
- **Work counters**: `output_bytes` falls everywhere a font or profile is
  embedded; `objects` and `font_objects` fall by two per Type 0 bundle;
  `cid_map_bytes` becomes `identity_cid_entries` (entries checked rather
  than bytes written).
